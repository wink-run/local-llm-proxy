# AI 资产价值认知 · 管理 · 变现闭环 —— 设计文档

日期:2026-07-25
状态:产品方案（指导后续实现优先级）

## 背景与目标

Token Bank 已具备资源中枢（MCP / Skill / Prompt / Agent）、投射门控、工作画像、「为你推荐」、闲置 Skill 清理、社区目录与闲置算力换积分等能力。但用户侧仍常见三类断层：

1. **无认知**：装了一堆 Skill / Prompt，却说不清「它们为我省了什么、赚了什么」
2. **难管理**：资产堆在列表里，活跃 / 闲置 / 未投射混在一起，不知道该留、该投、该清
3. **用不顺**：发现了却投不到 Agent、用的时候找不到、用完看不到结果反馈，更谈不上产生价值

**目标一句话：**

> 让用户一眼看见 AI 资产的价值 → 用最少动作管好库存 → 在真实工作流里顺手调用 → 把结果沉淀成可复用、可分享、可换积分的闭环。

对应三条产品主线：

| 主线 | 用户感知 | 产品手段 |
|---|---|---|
| **看得见价值** | 「这些资产在为我工作」 | 资产账本：调用次数、节省 Token/时间、命中场景、ROI |
| **管得住库存** | 「该留 / 该投 / 该清一目了然」 | 健康度分层 + 画像对齐 + 一键治理 |
| **用得出价值** | 「开口就能用，用完还能赚」 | 投射即可见 + 会话内召回 + 沉淀 / 分享 / 积分 |

---

## 已定决策

| # | 决策点 | 结论 |
|---|---|---|
| 1 | 资产范围 | **四类可纳管资源**：MCP / Skill / Prompt / Assistant（Agent）；Token / 额度 / 闲置算力作为「供给资产」单独计账，不与内容资产混列表 |
| 2 | 价值定义 | **三重价值**：效率（省 Token / 省轮次 / 省时间）、质量（任务成功率 / 复用次数）、变现（分享积分 / 圈子贡献） |
| 3 | 认知入口 | **资源页顶部资产账本条**（默认展开轻量数字）+ 盘点页「资产贡献」分区；不新建独立 App 模块 |
| 4 | 管理默认态 | **按健康度分层**：在用 · 已投射 · 闲置 · 未对齐画像；闲置扫描与清理沿用现有能力并前置到主路径 |
| 5 | 使用路径 | **保持「投射即可见」**：Agent 经 MCP / 原生 Skill 自主取用；用户侧补「一句话怎么用」与「最近被谁用过」 |
| 6 | 价值回流 | 每次命中资产 → 记账 → 反哺画像与推荐；优质资产可一键贡献社区目录换积分（与闲置算力积分体系对齐） |

## 问题拆解：三个断层

```
发现 / 纳管          投射 / 调用           结果 / 收益
     │                    │                    │
     ▼                    ▼                    ▼
  装进仓库  ──断层1──►  真正被 Agent 用  ──断层2──►  用户看见省了/赚了
  （目录多）            （投射少 / 找不着）         （无账本 / 无反馈）
```

产品不是「再做一个资源市场」，而是把现有链路补成闭环：

1. **认知**：把隐性收益显性化（数字 + 故事 + 对比）
2. **管理**：把库存变成可决策的分层，而不是平铺卡片
3. **使用**：把「纳管 → 投射 → 会话召回 → 沉淀」压到最短路径

## 方案一：看得见价值 —— 资产账本

### 1.1 每条资产的价值字段（数据）

在现有 `resources` / 投射 / Trace 之上补齐（或派生）指标，不要求用户手工填：

| 字段 | 含义 | 来源 |
|---|---|---|
| `use_count` | 被 Agent 实际取用次数 | `tb_get_prompt` / Skill 命中 / MCP tool 调用 Trace |
| `last_used_at` | 最近使用时间 | 同上 |
| `projected_agents` | 已投射 Agent 数 | `resource_projections` |
| `est_tokens_saved` | 估算节省 Token | 相对「无该资产时的基线轮次」启发式，或压缩 / 路由旁路已有节省 |
| `purpose_slugs` | 用途标签 | 现有 `resource-purpose` |
| `portrait_fit` | 与当前工作画像匹配度 | 画像 × tags / purpose |
| `value_tier` | 高 / 中 / 低 / 沉睡 | 由上面指标规则算出 |

> 原则：宁可给「本周被用 12 次 · 已投射到 Claude Code」这类硬事实，也不先上难解释的「价值分 87」。

### 1.2 资源页顶部：轻量账本条

一屏只讲一件事——**你的资产这周在干活吗？**

展示（示例文案）：

- 本周资产命中 **86** 次
- 已投射可用 **23** / 库存 **61**
- 沉睡（≥ N 天未用）**14** · 建议清理或重投
- 相对未用资产场景，估算少走 **x** 轮无效对话（有数据才显示）

点击数字下钻到对应分层列表；不放统计大盘、不占首屏营销位。

### 1.3 盘点页：资产贡献分区

与现有 Token / 费用盘点并列，增加「资产贡献」：

- Top 命中 Skill / Prompt
- 投射覆盖率（有多少纳管 Agent 已挂上关键资产）
- 闲置算力 / 社区分享积分（供给资产侧，链到「闲置赚钱」）

工作画像海报可附带一行：「本周最高频资产：代码审查 Prompt · 18 次」——强化对外认知与对内复盘。

### 1.4 认知话术（产品文案原则）

| 避免 | 改用 |
|---|---|
| 「AI 资产库」「数字化资产」 | 「会被 Agent 反复调用的技能与提示词」 |
| 「价值分 / 成长值」 | 「本周省了多少轮 / 命中多少次 / 换了多少积分」 |
| 空泛「提升效率」 | 「上次同类任务 6 轮 → 用『代码审查』后 2 轮」 |

用户建立认知靠**可核对的前后对比**，不是靠教育弹窗。

## 方案二：管得住库存 —— 健康度分层管理

### 2.1 默认视图：四层，而不是「全部卡片」

| 层 | 定义 | 主操作 |
|---|---|---|
| **在用** | `last_used_at` 在窗口内，或近 7 日 `use_count>0` | 查看命中详情、固定到常用 |
| **已投射未用** | 有投射但长期 0 命中 | 检查 Agent 是否真同步；给「一句话用法」；或取消投射 |
| **库存未投射** | 已纳管但未投射任何 Agent | 一键按画像推荐投射目标 |
| **沉睡** | 超过 `idleDays` 未用（复用现有闲置扫描） | AI 建议保留 / 清理；批量归档 |

「个性化推荐 / 社区目录」仍在下半区；**上半区个人资产改为分层**，避免「推荐很热闹、自己的库是黑洞」。

### 2.2 管理动作收敛为 5 个动词

用户只需记住：

1. **收** — 从推荐 / 目录纳管进个人库  
2. **投** — 投射到指定 Agent（可见才可用）  
3. **用** — 在 Agent 会话里按名或自然语言召回  
4. **留** — 标记常用 / 对齐画像用途  
5. **清** — 沉睡清理（现有 idle cleanup 升级为分层入口）

卡片上的次要按钮（编辑、标签、详情）收进更多菜单，避免和这 5 个动词抢注意力。

### 2.3 画像对齐治理

复用工作画像 + `resource-purpose`：

- 与画像用途高度重合 → 提示「建议投射到主 Agent」
- 与画像无关且长期未用 → 进沉睡候选
- 画像变了（例如从内容转向开发）→ 资源页轻提示「有 6 条资产不再匹配当前工作，是否重投 / 归档」

管理目标不是「库越大越好」，而是**可用密度**：已投射且在用 / 总库存。

### 2.4 依赖与冲突可见

纳管 Skill / Assistant 时级联依赖已有基础；需在卡片上明示：

- 依赖的 MCP 是否绿灯（复用内置 MCP 状态灯）
- 投射目标 Agent 是否仍纳管
- 同名冲突 / 重复资产合并建议

「管得好」= 断链资产为零 + 沉睡可控 + 投射覆盖合理。

## 方案三：用得出价值 —— 最短使用路径与变现

### 3.1 使用路径（保持单一心智）

```
纳管 → 投射到 Agent → Agent 会话内经 MCP/Skill 取用 → Trace 记命中 → 账本更新
```

Prompt 继续走 `tokenbank-prompts`（`tb_get_prompt` / `tb_list_prompts`）投射可见；Skill / MCP 走既有同步。不新增第三条「手动复制粘贴」主路径。

### 3.2 降低「会装不会用」

每条已投射资产展示：

- **一句话用法**（可模板生成）：  
  `对 Claude Code 说：使用「代码审查」prompt 审查当前分支`
- **最近命中**：哪个 Agent、何时、关联会话入口（跳转 Trace / 会话）
- **未命中诊断**：已投射但 0 次 → 检查 MCP 是否写入、Agent 是否重启、名称是否可发现

### 3.3 会话中的「顺手」

优先做低摩擦增强，而不是新 IDE：

1. Agent 侧：`tb_list_prompts` / Skill 列表保持短描述，便于模型选择  
2. TB 侧：游乐场 / 主 Agent 编排时，按当前任务用途自动提示「可挂载的 3 条资产」  
3. 用完后 toast / 时间线一条：「已命中『代码审查』· 计入本周资产账本」

反馈闭环是认知的燃料：用一次，看见一次价值。

### 3.4 产生价值的三条出口

| 出口 | 机制 | 用户收益 |
|---|---|---|
| **自用复利** | 命中 → 画像强化 → 更准推荐 → 更少从零写 Prompt | 越用越快 |
| **团队 / 圈子** | 资产打包分享到圈子（权限可控） | 减少重复建设 |
| **社区积分** | 优质 Skill/Prompt 贡献目录；闲置算力继续走现有贡献公式 | 积分可消费共享模型 |

变现不另起炉灶：内容资产贡献与算力贡献共用积分账户，盘点页同一「赚到」入口展示。

### 3.5 「从使用中沉淀」自动收割

当 Trace 发现：

- 用户反复粘贴相似长指令 → 建议一键存为 Prompt 资产并投射  
- 某 Skill 高频成功 → 建议固定到主 Agent、分享到圈子  
- 本地模型闲置 + 有额度 → 提示打开社区分享（既有「闲置赚钱」）

沉淀动作必须**一键可完成**，并立刻出现在「在用 / 已投射」层，而不是掉进未整理库存。

## 信息架构（落位，不新开一级导航）

```
资源页
├─ 顶部：本周资产账本条（认知）
├─ Tab：我的资产（默认 · 健康度分层 · 管理）
│   ├─ 在用 / 已投射未用 / 未投射 / 沉睡
│   └─ 卡片：投 · 用 · 清 + 一句话用法 + 命中数
├─ Tab：为你推荐（发现 · 现有 PersonalizedRecommend + 目录）
└─ 次要：新建 / 扫描闲置（沉睡层入口）

盘点页
└─ 新增分区：资产贡献 + 积分入口（认知强化）

网关 / 游乐场
└─ 任务上下文中的「可挂载资产」轻提示（使用）
```

不新增「AI 资产」一级 Tab，避免和「资源」语义重复；对外文案把「资源」逐步说成用户能懂的「技能 / 提示词 / 智能体」，账本里再用「资产」统称。

## 关键路径（实现优先级）

### P0 — 认知与管理最小闭环（先做）

1. 从 Trace / MCP / Skill 调用写入 `use_count` / `last_used_at`  
2. 资源页「我的资产」按四层分组 + 顶部账本条（命中次数、投射覆盖、沉睡数）  
3. 已投射卡片展示「一句话用法」+ 命中次数  
4. 沉睡层接入现有 idle 扫描 / AI 清理建议  

### P1 — 用得顺

1. 未命中诊断（投射了但 0 次的检查清单）  
2. 游乐场任务侧「推荐挂载 3 条」  
3. 命中后的轻反馈写入时间线 / toast  

### P2 — 价值放大

1. 盘点页资产贡献与海报文案  
2. 反复指令 → 一键沉淀为 Prompt  
3. 资产贡献社区目录换积分（与现有积分体系对接）

## 成功指标

| 指标 | 意图 |
|---|---|
| 纳管资产的投射率 | 装了且挂到 Agent 上 |
| 已投射资产的 7 日命中率 | 挂了且真的在用 |
| 沉睡资产占比下降 | 库在变干净 |
| 用户周活里「资源页账本曝光 → 发生投/清/用」转化 | 认知促成行动 |
| 由资产沉淀 / 分享产生的积分占比 | 开始产生外部价值 |

---

## 非目标（本阶段不做）

- 独立「资产交易所」或复杂定价市场  
- 强制用户给每条资产打价值分  
- 改变「投射即可见」的单一使用模型  
- 用空洞的游戏化等级替代真实命中与节省数据

## 一句话产品原则

> **资产不是收藏夹，是会进会话、会进账本、会进积分的生产力单元。**  
> 先让用户看见命中与节省，再让管理变成分层决策，最后让每一次使用自动加厚下一次推荐与可变现库存。
