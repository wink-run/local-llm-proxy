# 场景路由组合增强：文本主模型 + 识图助手（vision_assist）

日期：2026-08-10  
状态：已批准（待实现计划）

## 问题

纯文本主模型遇到带图请求时，网关目前只能把图片剥成 `[图片]` 占位，无法利用多模态模型的识图能力。用户希望在场景路由里把「文本主模型」与「多模态助手」组合：有图时先让助手描述图片，再把描述交给主模型推理，从而让文本主模型具备可用的多模态能力。

## 目标

- 场景路由步骤可绑定可选识图助手（`vision_assist`）。
- **仅当请求含图片时**触发助手；无图路径零开销、行为不变。
- 将图片部位 **替换** 为描述文本后调用主模型（给主模型「增加描述」，主模型不再直接收图）。
- 助手失败时 **降级** 为现有 `[图片]` 占位并继续主推理，不阻断对话。
- OpenAI `/v1/chat/completions` 与 Anthropic `/v1/messages` 均支持。
- 路由详情与用量能区分「助手段」与「主模型段」。

## 非目标（首期）

- 视频 / 音频增强。
- 按图多次串行调用助手（首期一次调用带全部图）。
- 助手结果缓存。
- 全局模型配对表（与场景无关的自动配对）。
- 把现有 `steps[]` failover 语义改成通用流水线（避免与后备池冲突）。

## 方案选择

采用 **网关内联预处理（方案 A）**：

- 在选定主模型步骤、即将 `callProvider` 之前做识图预处理。
- 复用现有 `internalComplete`（分类器同款内部调用）并扩展为支持多模态输入。
- 复用 / 对齐现有 `stripImages*`、`modelSupportsVision` 路径。

不采用：

- **B**：把 vision→text 做成普通 `steps` 链——与现有 failover 语义冲突。
- **C**：各客户端自行改写——无法统一落在「场景路由策略」上。

可发现性：在默认场景中增加一条预置模板路由（外观像独立策略，实质仍是带 `vision_assist` 的普通场景步骤）。

## 配置形态

挂在场景路由 **主模型步骤** 上：

```yaml
steps:
  - model: deepseek-v4-pro          # 文本主模型
    vision_assist:
      model: gpt-5.6-luna           # 多模态助手（须能看图）
      prompt: "用简洁中文描述图中与用户问题相关的内容，不要猜测未见信息。"  # 可选
      max_tokens: 512               # 可选
```

约定：

- 仅当该步被选为本次主调用、且请求体含图片时启用。
- 助手 `model` 解析方式与普通 `steps[].model` 相同（在任意拥有该模型的供给源中解析）。
- `prompt` / `max_tokens` 有网关默认值；UI 可覆盖。
- 预置示例路由（如「文本+识图增强」）写入 `scenes.default.yaml`（或等价默认场景配置）。

## 请求流水线

```
请求含图？ ──否──▶ 原样调主模型
    │是
    ▼
步骤有 vision_assist.model？ ──否──▶ 现有逻辑（不支持视觉则剥成 [图片]）
    │是
    ▼
抽取全部图片 → 一次非流式调助手（扩展后的 internalComplete）
    │
    ├─ 成功 → 各 image / image_url 位替换为「[图片N]：{描述}」→ 调主模型（可流式）
    └─ 失败 → 降级 [图片] → 仍调主模型
```

细节：

1. **触发位置**：场景步即将调用主模型之前（含 keyScene / 策略展开后落到具体 `step.model` 的路径）。
2. **多图**：一次助手调用携带全部图片；要求助手按图片序号分段描述，网关按序写回对应部位。
3. **替换策略**：去掉原始图片块，在原 content 结构中写入描述文本（等价于「给模型增加描述」）。
4. **主模型已支持视觉**：仍按配置走助手替换；主模型阶段只收文本描述（不重复塞原图），与产品语义一致。
5. **协议**：同时处理 OpenAI `image_url` 与 Anthropic `image`（含 base64 / url）。
6. **流式**：等助手完成后再对主模型开流；首包延迟增加识图耗时。
7. **错误**：助手超时、4xx/5xx、解析失败 → 降级 `[图片]`，主对话继续。
8. **可观测性**：
   - 路由详情记录助手段（模型、耗时、成败）与主模型段。
   - 用量分别记助手与主模型（两段都走现有 stats/usage 通道，或等价扩展字段）。

## UI

- 场景路由编辑：有 `model` 的步骤旁增加「识图增强」下拉（候选：`type=vision` 或已知可看图的模型）。
- 可选展开：自定义 `prompt` / `max_tokens`（默认折叠）。
- 默认场景列表展示预置「文本+识图增强」模板。

## 验收标准

1. 无图请求：不调用助手，行为与现状一致。
2. 有图且配置了 `vision_assist`：主模型请求中无原始图片块，仅有描述文本；路由详情可见助手段。
3. 助手失败：主对话仍成功，图片位为 `[图片]`。
4. OpenAI chat completions 与 Anthropic messages 路径均通过有图用例。
5. 未配置 `vision_assist` 的步骤：保持现有剥图 / 透传视觉行为。
