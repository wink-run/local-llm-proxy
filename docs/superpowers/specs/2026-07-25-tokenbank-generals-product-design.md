## 1. 一句话产品

> **Token Bank 是你的私人武将库与兵器库：把智能体和 Skill/Prompt 养在本地，Cursor / Claude Code / Codex 随时点将出战；闲着的将、兵器和算力还能出租换积分——不是又一个吃灰的 AI 笔记库。**

与五条主线对齐：

| 主线 | 武将库叙事里的含义 |
|---|---|
| 用的明白 | 每次点将、每条算力路都进 Trace / 息票 |
| 用的节省 | 场景路由选算力；点将对口武将少绕弯 |
| 用的简单 | 不改客户端；MCP 点将，开口即用 |
| 越用越懂你 | 画像推荐该启用哪员将、哪件兵器 |
| 闲置赚钱 | 闲将 / 闲兵 / 闲算力出租换积分 |

## 2. 为什么现在做（痛点 → 反转）

| 用户痛点 | 常见假方案 | Token Bank 反转 |
|---|---|---|
| Skill / Prompt / 智能体越装越乱 | 再建一个「资源管理」页 | **武将库 + 兵器库**，只认出战与出租 |
| 收藏了从不用 | 标签、笔记本、第二大脑 | **启用=投射+口令**；藏而不用非法 |
| 想让 Cursor「突然会审代码」 | 改系统提示 / 插件墙 | **同会话 MCP 点将**，披甲自打 |
| 网关乱改客户端工具 | 注入 tool schema | **零侵入**：只应答，不篡改协议 |
| 闲置只会心疼 | 纯清理按钮 | **自用或出租**，流通才有价值 |

**宣传禁忌：** 资产库、知识库、纳管中心、第二大脑。  
**宣传主句：** 让你的 Cursor / Claude **立刻多会一件事**；闲了还能出租。

## 3. 世界观与角色

```
                    ┌──────────── Token Bank ────────────┐
                    │  武将库 (assistant)                 │
                    │  兵器库 (Skill / Prompt / MCP)      │
                    │  算力路 (场景路由，不是将)            │
                    └──────────┬───────────┬─────────────┘
                               │自用点将    │闲置出租
                               ▼           ▼
                    Cursor / Claude     社区·圈子·积分
                    Code / Codex
                         ▲
                         │ 主公下令（MCP）
                         │ 武将不自己冲锋
```

| 角色 | 是谁 | 关键动作 |
|---|---|---|
| **主公** | Cursor / Claude Code / Codex… | 点将、打仗 |
| **武将** | 资产里的智能体 | 被点中才出战 |
| **兵器** | Skill / Prompt | 随将出战或单件取用 |
| **军需** | 场景路由 / 供给源 | 选哪条算力路 |
| **客栈** | 社区目录 / 圈子 | 租将、租兵、租算力 |

## 4. 两条生命线（必须同时成立）

### 4.1 自用：启用 → 点将 → 命中

```
发现（场景货架 / 画像推荐）
  → 启用到主公（入库 ∧ 投射 ∧ 口令）
  → 用户对 Cursor/Claude/Codex 说话点将
  → MCP：tb_list_resources(type=assistant) → tb_get_resource
  → 主公同会话披甲执行（不默认拉子进程）
  → 命中记账 / 息票（看见价值）
```

### 4.2 出租：闲置 → 上架 → 被用 → 积分

```
长期未点将的武将/兵器 或 闲置算力
  → 上架目录 / 圈子 / 社区分享
  → 他人启用或调用
  → 积分入账（与算力结息同一账户语言）
```

未自用也未出租 → Hit-or-Exit（冷藏 / 删除 / 催上架）。  
**库的合法性来自流通，不来自体积。**

## 5. 客户端怎么调用（完整故事）

### 5.1 零侵入前提

- Token Bank 把 `tokenbank-resources`（及 prompts 等）sync 进：  
  - Cursor → `~/.cursor/mcp.json`  
  - Claude Code → `~/.claude.json`  
  - Codex → `~/.codex/config.toml`  
- 带 `TB_CLIENT_ID`，只暴露**已投射给该主公**的将与兵器  
- **不改**各客户端工具协议；模型按 MCP 描述自行调用  

### 5.2 点将（直连会话 · 默认主路径）

用户：「用『代码审查』智能体审一下当前改动」

| 步 | 谁 | 做什么 |
|---|---|---|
| 1 | 主公模型 | `tb_list_resources({ type: "assistant", query: "审查" })` |
| 2 | 主公模型 | `tb_get_resource({ type: "assistant", name: "…" })` |
| 3 | TB MCP | 校验投射 → 返回 **soul + 绑定 Prompt/Skill 全文** |
| 4 | 主公 | **仍在当前会话**按正文执行 |

兵器单件同理：`tb_list_prompts` → `tb_get_prompt`（已落地）。

### 5.3 派发（编排 · 专线）

仅 Token Bank 游乐场 / 编排注入 `tokenbank-agent-bridge` 时：  
`tb_dispatch_agent({ agent_id: "assistant:…" })` → TB 拉起 runtime。  
**日常 IDE/CLI 会话不要默认走这条。**

### 5.4 产品承诺（写进能力文案）

> 点将 = 拿兵书自己打。  
> 派发 = 让武将下场打。  
> 主公不下令，谁也别自己冲。

## 6. 用户旅程（三种人各 30 秒）

### A. 普通用户（获客主路径）

1. 纳管 Cursor  
2. 场景货架点「启用代码审查到 Cursor」  
3. 复制口令，在 Cursor 说一句  
4. 审完，角落一张息票：「命中 · 代码审查」  
5. **从未打开「已纳管」列表也能成功**

### B. 极客 / 多主公

1. 一将投射给 Claude Code + Cursor  
2. 两边都能 list/get  
3. Trace 看见哪个主公点了哪将  
4. 闲将一键上架出租  

### C. 贡献者

1. 本地模型 / 额度过夜贡献（已有）  
2. 闲置武将/兵器上架（补齐）  
3. 盘点页同一句：「昨夜出手：算力 +128 · 武将被点 6 次」

## 7. 信息架构（吸引人且不落笔记坑）

```
对外主故事（首屏）
├─ 网关：接上你的主公（Claude / Cursor / Codex）
├─ 让 AI 更强：场景货架（按「事」不是按类型）
│    CTA =「启用到 {主公}」+ 口令
└─ 出手反馈：息票 / 托盘一句

进阶（后门）
├─ 武将库 · 兵器库（原资源页，改叙事）
│    在用 / 未打穿 / 可出租·沉睡
└─ 出租台：算力 + 将 + 兵器

盘点
└─ 省了 / 赚了 / 点将命中（结果，不晒库存数）
```

**一级导航不叫「资产」对外可逐步改为「队伍 / 能力」**（实现可分期改文案）。

## 8. 关键界面创意（克制、好传播）

| 触点 | 做什么 | 传播点 |
|---|---|---|
| 启用成功 | 弹出**口令卡**：「对 Cursor 说……」 | 可截图教朋友 |
| 点将命中 | **息票**小条（将名 · 主公 · 少绕几轮） | 价值可见 |
| 周报 | **出手周报**（命中↑庆祝；库存↑命中↓报警） | 非开箱晒库 |
| 沉睡 | **休眠公函**→ 重启用 / 出租 / 冷藏 | 有尊严的清理 |
| 出租 | 与算力贡献同一「结息」语言 | 闲置赚钱延展 |

金库门、星图等仅品牌彩蛋，**禁止当获客主视觉**。

## 9. 与现网能力的咬合（少造轮子）

| 现网 | 产品中的角色 |
|---|---|
| `tokenbank-resources` | **将帅榜 + 点将**（增强 get/门控） |
| `tokenbank-prompts` | 兵器单件 |
| 投射 / sync | 启用包技术底座 |
| PersonalizedRecommend | 升格为场景货架 |
| 场景路由 | 军需/算力路（保持正交） |
| agent-bridge 派发 | 编排专线 |
| 社区算力分享 | 出租的算力腿；将/兵出租为延伸 |
| Trace / local_stats | 命中与息票数据 |

P0 工程焦点见 [产品审查 §4](./2026-07-25-product-audit-generals-logic.md)：改 `resources-mcp` / capabilities / 启用 CTA，**不新建 list MCP**。

## 10. 成功指标（产品健康度）

| 指标 | 好信号 |
|---|---|
| 启用 → 48h 首次点将/取兵器 | 堵住藏而不用 |
| 零「资源库」UV 的成功启用 | 普通用户可零管理 |
| 直连会话 get(assistant) 次数 ≫ 无意义 dispatch | 点将主路径正确 |
| 闲置上架率 / 被租用率 | 出租腿活着 |
| 对外分享含「变强结果」占比 | 好宣传 |

负向：资源页停留↑、命中↓ → 又在诱导整理。

## 11. 路线图（叙事顺序 = 发布顺序）

### 第一章 · 能打（P0）

- get(assistant) 出战全文 + 投射门控  
- capabilities：list→get→自打  
- CTA：启用到主公 + 口令  
- 文案去「先纳管进库」  

**发布故事：**「对 Cursor 说一句，召出你的代码审查武将。」

### 第二章 · 不囤（P1）

- 命中记账、息票、Hit-or-Exit  
- 场景货架按「事」排  
- 出手周报  

**发布故事：**「用不上的将，系统会催你重启用或送去出租。」

### 第三章 · 能租（P2）

- 闲将/闲兵上架换积分  
- 与算力结息同一盘点语言  
- 可选 `tb_suggest_general`  

**发布故事：**「队伍能出战，也能过夜赚安家费。」

## 12. 对外话术包（可直接用）

**15 秒：**  
装上 Token Bank，你的 Cursor / Claude 马上多会一件事。不用建库。闲了还能出租换积分。

**60 秒：**  
把智能体当成武将、Skill/Prompt 当成兵器，养在本地武将库里。打仗时主公（Cursor 等）自己用 MCP 点将，拿回兵书就在当前对话里干——我们不改你的客户端，也不替你乱开子进程。闲置的将、兵器和算力可以出租到社区，换积分继续用更好的模型。这不是笔记软件，是一支能打仗、能生息的队伍。

**不要说：** 个人知识库、Prompt 收藏夹、AI 资产管理系统。

## 13. 设计红线（评审用）

1. 普通用户能否不进资源库就启用并点将成功？  
2. 客户端路径是否 list/get 同会话，而非误导去 dispatch？  
3. 闲置下一步是出战或出租，还是继续待在「已纳管」？  
4. 截图拿去宣传，秀的是变强结果还是仓库？  

任一条失败 → 打回。

---

## 14. 收束

Token Bank 已有网关、路由、Trace、投射与资源 MCP——缺的不是又一个库，而是**把库说成队伍、把调用收成点将、把闲置收成出租**。  

做完第一章，用户感知应从「我又多了一个要整理的 App」变成：

> **我的主公随时能点将；我的队伍闲着也能赚钱。**
