## 1. 一句话产品

> **Token Bank 是你的私人武将库与兵器库：把智能体和 Skill/Prompt 养在本地，Cursor / Claude Code / Codex 随时点将出战；闲着的将、兵器和算力还能出租换积分——不是又一个吃灰的 AI 笔记库。**

与五条主线对齐：

| 主线 | 武将库叙事里的含义 |
|---|---|
| 用的明白 | 每次点将、每条算力路都进 Trace / 息票 |
| 用的节省 | 场景路由选算力；点将对口武将少绕弯 |
| 用的简单 | 不改客户端；MCP 点将，开口即用 |
| 越用越懂你 | 画像推荐该启用哪员将、哪件兵器 |
| 闲置赚钱 | 闲将 / 闲兵 / 闲算力出租换积分 |

## 2. 为什么现在做（痛点 → 反转）

| 用户痛点 | 常见假方案 | Token Bank 反转 |
|---|---|---|
| Skill / Prompt / 智能体越装越乱 | 再建一个「资源管理」页 | **武将库 + 兵器库**，只认出战与出租 |
| 收藏了从不用 | 标签、笔记本、第二大脑 | **启用=投射+口令**；藏而不用非法 |
| 想让 Cursor「突然会审代码」 | 改系统提示 / 插件墙 | **同会话 MCP 点将**，披甲自打 |
| 网关乱改客户端工具 | 注入 tool schema | **零侵入**：只应答，不篡改协议 |
| 闲置只会心疼 | 纯清理按钮 | **自用或出租**，流通才有价值 |

**宣传禁忌：** 资产库、知识库、纳管中心、第二大脑。  
**宣传主句：** 让你的 Cursor / Claude **立刻多会一件事**；闲了还能出租。

## 3. 世界观与角色

```
                    ┌──────────── Token Bank ────────────┐
                    │  武将库 (assistant)                 │
                    │  兵器库 (Skill / Prompt / MCP)      │
                    │  算力路 (场景路由，不是将)            │
                    └──────────┬───────────┬─────────────┘
                               │自用点将    │闲置出租
                               ▼           ▼
                    Cursor / Claude     社区·圈子·积分
                    Code / Codex
                         ▲
                         │ 主公下令（MCP）
                         │ 武将不自己冲锋
```

| 角色 | 是谁 | 关键动作 |
|---|---|---|
| **主公** | Cursor / Claude Code / Codex… | 点将、打仗 |
| **武将** | 资产里的智能体 | 被点中才出战 |
| **兵器** | Skill / Prompt | 随将出战或单件取用 |
| **军需** | 场景路由 / 供给源 | 选哪条算力路 |
| **客栈** | 社区目录 / 圈子 | 租将、租兵、租算力 |

## 4. 两条生命线（必须同时成立）

### 4.1 自用：启用 → 点将 → 命中

```
发现（场景货架 / 画像推荐）
  → 启用到主公（入库 ∧ 投射 ∧ 口令）
  → 用户对 Cursor/Claude/Codex 说话点将
  → MCP：tb_list_resources(type=assistant) → tb_get_resource
  → 主公同会话披甲执行（不默认拉子进程）
  → 命中记账 / 息票（看见价值）
```

### 4.2 出租：闲置 → 上架 → 被用 → 积分

```
长期未点将的武将/兵器 或 闲置算力
  → 上架目录 / 圈子 / 社区分享
  → 他人启用或调用
  → 积分入账（与算力结息同一账户语言）
```

未自用也未出租 → Hit-or-Exit（冷藏 / 删除 / 催上架）。  
**库的合法性来自流通，不来自体积。**

## 5. 客户端怎么调用（完整故事）

### 5.1 零侵入前提

- Token Bank 把 `tokenbank-resources`（及 prompts 等）sync 进：  
  - Cursor → `~/.cursor/mcp.json`  
  - Claude Code → `~/.claude.json`  
  - Codex → `~/.codex/config.toml`  
- 带 `TB_CLIENT_ID`，只暴露**已投射给该主公**的将与兵器  
- **不改**各客户端工具协议；模型按 MCP 描述自行调用  

### 5.2 点将（直连会话 · 默认主路径）

用户：「用『代码审查』智能体审一下当前改动」

| 步 | 谁 | 做什么 |
|---|---|---|
| 1 | 主公模型 | `tb_list_resources({ type: "assistant", query: "审查" })` |
| 2 | 主公模型 | `tb_get_resource({ type: "assistant", name: "…" })` |
| 3 | TB MCP | 校验投射 → 返回 **soul + 绑定 Prompt/Skill 全文** |
| 4 | 主公 | **仍在当前会话**按正文执行 |

兵器单件同理：`tb_list_prompts` → `tb_get_prompt`（已落地）。

### 5.3 派发（编排 · 专线）

仅 Token Bank 游乐场 / 编排注入 `tokenbank-agent-bridge` 时：  
`tb_dispatch_agent({ agent_id: "assistant:…" })` → TB 拉起 runtime。  
**日常 IDE/CLI 会话不要默认走这条。**

### 5.4 产品承诺（写进能力文案）

> 点将 = 拿兵书自己打。  
> 派发 = 让武将下场打。  
> 主公不下令，谁也别自己冲。

## 6. 用户旅程（三种人各 30 秒）

### A. 普通用户（获客主路径）

1. 纳管 Cursor  
2. 场景货架点「启用代码审查到 Cursor」  
3. 复制口令，在 Cursor 说一句  
4. 审完，角落一张息票：「命中 · 代码审查」  
5. **从未打开「已纳管」列表也能成功**

### B. 极客 / 多主公

1. 一将投射给 Claude Code + Cursor  
2. 两边都能 list/get  
3. Trace 看见哪个主公点了哪将  
4. 闲将一键上架出租  

### C. 贡献者

1. 本地模型 / 额度过夜贡献（已有）  
2. 闲置武将/兵器上架（补齐）  
3. 盘点页同一句：「昨夜出手：算力 +128 · 武将被点 6 次」

```
对外主故事（首屏）
├─ 网关：接上你的主公（Claude / Cursor / Codex）
├─ 让 AI 更强：场景货架（按「事」不是按类型）

├─ 武将库 · 兵器库（原资源页，改叙事）
│    在用 / 未打穿 / 可出租·沉睡
└─ 出租台：算力 + 将 + 兵器

盘点
└─ 省了 / 赚了 / 点将命中（结果，不晒库存数）
```

**一级导航不叫「资产」对外可逐步改为「队伍 / 能力」**（实现可分期改文案）。

## 8. 关键界面创意（克制、好传播）

| 触点 | 做什么 | 传播点 |
|---|---|---|
| 启用成功 | 弹出**口令卡**：「对 Cursor 说……」 | 可截图教朋友 |
| 点将命中 | **息票**小条（将名 · 主公 · 少绕几轮） | 价值可见 |
| 周报 | **出手周报**（命中↑庆祝；库存↑命中↓报警） | 非开箱晒库 |
| 沉睡 | **休眠公函**→ 重启用 / 出租 / 冷藏 | 有尊严的清理 |

金库门、星图等仅品牌彩蛋，**禁止当获客主视觉**。

## 12. 对外话术包（可直接用）

**15 秒：**  
装上 Token Bank，你的 Cursor / Claude 马上多会一件事。不用建库。闲了还能出租换积分。

**60 秒：**  
把智能体当成武将、Skill/Prompt 当成兵器，养在本地武将库里。打仗时主公（Cursor 等）自己用 MCP 点将，拿回兵书就在当前对话里干——我们不改你的客户端，也不替你乱开子进程。闲置的将、兵器和算力可以出租到社区，换积分继续用更好的模型。这不是笔记软件，是一支能打仗、能生息的队伍。

**不要说：** 个人知识库、Prompt 收藏夹、AI 资产管理系统。

## 14. 场景路由会不会鸡肋？如何与点将融合？

### 14.1 单独看：确实偏「军需仓」

若场景路由**只**暴露「综合最优 / 实惠 / 速度 / 免费源…」，和武将库并列成两个后台页，用户体感容易是：

- 点将管本事，路由管价钱——**脑子里要拼两张表**  
- 路由页缺少「为谁、打什么仗」的上下文 → 像高级设置，**像鸡肋**  
- 和「启用武将」无联动 → 选了将仍可能走贵模型，价值说不清  

所以：**实体保持正交（路由≠武将），体验必须编队融合**——不能做成两个互不说话的仓库。

### 14.2 融合模型：出战编制 = 武将 × 军需

```
一次出战
├─ 点将：谁的本事（assistant + 兵器）     ← resources MCP
└─ 军需：走哪条算力路（场景路由 / 供给） ← 现有 scene_routes
        主公（Cursor…）在会话里打仗
```

| 层 | 用户话 | 产品对象 |
|---|---|---|
| 本事 | 「上代码审查」 | 武将 |
| 军需 | 「这次走实惠 / 走本地 / 走订阅」 | 场景路由（可绑在应用或默认） |
| 编制 | 「审查这仗：审查将 + 实惠路」 | **出战预设**（新产品胶合层，极轻） |

**不要**把场景路由改成选将器；**要**在启用武将、Tray、息票里同时露出「当前军需」。

### 14.3 胶合方式（由轻到重）

**L1 · 叙事与同屏（P0，几乎无新实体）**

- 启用武将成功卡：口令 + 一行「当前 Cursor 军需：实惠优先」  
- 息票：命中武将 **和** 实际走的路由/模型  
- 资源/推荐文案：本事与省钱分开说，但同卡展示  

**L2 · 出战预设（P1，轻量配置）**

- 可选「编制」：`{ generalId, sceneRouteId, clientId }` 三元组  
- 启用时默认带上该主公当前绑定路由；用户可一键「这仗改走本地」  
- 仍不合并表结构；预设只是快捷指针  

**L3 · 智能编队建议（P2）**

- 画像：审查类任务 → 推荐「审查将 + 本地/实惠路」  
- 与 `tb_list_resources` / 路由绑定只读查询配合；**路由切换仍走网关已有绑定**，MCP 点将不改模型协议  

### 14.4 结论

| 问题 | 答案 |
|---|---|
| 场景路由是否鸡肋？ | **单独做页容易鸡肋**；编进「出战编制」就变成省钱/稳定的军需腿 |
| 和点将如何融合？ | **正交存储、编队体验**：将管本事，路管算力，Tray/启用/息票三者同屏 |
| 会冲击模型纳管吗？ | **否**；只加展示与可选预设指针，不改 scene_routes 引擎 |

## 15. Tray 浮窗如何显性化这套设计

今日 Tray（`tray-popover`）已有：网关状态、今日上下行、贡献开关、圈子、**活跃应用 + 路由标签 + 测速**。  
缺的是：**队伍（点将）腿**——用户看不出武将库的存在。

### 15.1 信息架构（浮窗一屏）

```
Header    Token Bank · 今日出手摘要
Deck      网关 | 用量 | 贡献(出租算力) | 圈子
── 主公 ── 活跃应用（现有）
          每行：应用名 · 军需(路由) · TTFT · 今日 token
── 队伍 ── 今日点将 / 可召武将（新增 · 显性化核心）
          Top 口令卡 1～3 · 一键复制
── 出租 ── 贡献中？昨夜利息（现有胶囊强化文案）
Footer    主面板 · 测速 · 退出
```

原则：浮窗 **不是资源库**；只放「立刻能用的编制信号」。

### 15.2 「队伍」区具体内容

| 元素 | 作用 | 数据 |
|---|---|---|
| 今日点将 N 次 | 证明库在打仗，不是收藏 | MCP get(assistant)/get_prompt 命中计数 |
| 口令卡 ×3 | 显性化点将：复制即去主公会话粘贴 | 已投射且近用/推荐的 assistant 显示名 |
| 空态 | 「启用一员将到 Cursor」→ 打开场景货架 | 深链主面板 |
| 军需小字 | 口令卡下：「经 Cursor · 军需 实惠优先」 | 该 app 当前 scene route |

点击口令卡 = 复制「用『{武将名}』…」；不在 Tray 里展开全文 soul（防变成笔记浏览）。

### 15.3 Deck 文案微调（出租腿显性化）

| 现文案 | 建议 |
|---|---|
| 贡献 / Share | **出租算力**（运行中 / 未出租） |
| 仅帖子数 | 可加「昨夜 +积分」（有数据才显示） |

后续 P2：Deck 增加「闲将可租」角标（有沉睡可上架时），点进出租台——仍避免 Tray 变管理后台。

### 15.4 与测速、应用行的关系

- 应用行继续显示 **军需（路由）+ TTFT**：这是军需腿的显性化，保留并强化标签可读名（实惠优先，而非裸 id）  
- 测速 = 军需体检；点将口令 = 本事召唤——**并列，不互相替代**  
- 副标题示例：`出手 12 · 点将 3 · 军需均 TTFT 420ms`

### 15.5 实现落点（Tray）

| 改动 | 模块 |
|---|---|
| state 增加 `generalsToday` / `quickInvokes[]` / 每 app `routeDisplayName` | `tray-popover.js` `buildState` |
| UI「队伍」区块 + 复制口令 | `tray-popover.html` |
| 命中计数读取 | resource-manager / 本地 stats（与点将 P0 记账对齐） |
| 深链「去启用武将」 | `showMainWindow` + navigate resources/recommend |

P0 Tray 最小集：**口令卡 + 今日点将数 + 应用行军需名**；其余出租文案可先改 label。

## 16. 收束

Token Bank 已有网关、路由、Trace、投射与资源 MCP——缺的不是又一个库，而是**把库说成队伍、把调用收成点将、把闲置收成出租、把路由收成军需编队，并在 Tray 一屏亮出来**。  

做完第一章，用户感知应从「我又多了一个要整理的 App」变成：

> **托盘里能看见队伍和军需；主公随时能点将；闲着还能出租赚钱。**
