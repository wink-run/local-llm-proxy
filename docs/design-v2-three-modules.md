# Token Bank 产品升级设计说明 v2

> 状态：设计讨论稿
> 日期：2026-05-20

---

## 背景与升级目标

当前 Token Bank 是一个「贡献本地 LLM 算力换积分」的共享网络。Worker 已支持通过
`base_url + token + models` 接入任意 OpenAI 兼容接口，即持有正规 API Key 的用户
已可作为贡献者参与网络。

本次升级围绕三大板块重构产品结构，目标是：
**让「没有 GPU」的普通用户也能低成本使用和贡献，同时为消费者提供智能路由降低调用成本。**

## 板块一：模型接入（本地网关 Proxy）

### 1.1 定位

Token Bank 客户端在本地启动一个 OpenAI 兼容网关（`http://localhost:PORT/v1`）。
用户将所有 AI 工具（Claude Code、Cursor、Continue 等）统一指向本地网关，
网关根据用户选择的策略自动决定走哪条供给链路，**用户无需感知底层细节**。

### 1.2 两种路由策略

**省钱优先（Cost-First）**

按成本从低到高依次尝试，上层不可用才向下降级：

```
① 免费 Provider（Groq / Ollama / GitHub Models 等，零成本）
       ↓ 超出限额 / 不可用
② 用户分享网络（消耗本地积分，极低成本）
       ↓ 积分不足 / 无可用 Worker
③ 订阅 Provider（消耗已付费订阅额度）
       ↓ 不可用 / 超限
④ 付费 API（正规 API Key，最终兜底）
```

**质量优先（Quality-First）**

按模型能力从高到低优先保证效果：

```
① 付费旗舰 API（Claude Opus / GPT-4o，最佳质量）
       ↓ 不可用
② 订阅 Provider（质量接近旗舰）
       ↓ 不可用
③ 用户分享网络（高质量 Open 模型，如 Qwen3-32B）
       ↓ 无可用 Worker
④ 免费 Provider（兜底）
```

### 1.3 模型名映射

用户工具请求模型名（如 `claude-3-5-sonnet`），网关内部映射到实际可用资源：

| 请求模型 | 省钱优先 | 质量优先 |
|---------|---------|---------|
| `claude-3-5-sonnet` | 分享网络 Qwen3-32B | 订阅 Claude Pro |
| `gpt-4o` | Groq Llama3-70B | 付费 OpenAI API |
| `claude-3-haiku` | Ollama Qwen3-7B | 分享网络 Qwen3-7B |

映射表由管理员在后台配置，用户可在本地 UI 覆盖特定模型的路由规则。

### 1.4 Prompt Cache 自动注入

对所有经过本地网关的 Anthropic 请求，自动检测系统 prompt 长度：
- 超过 1024 token 的系统 prompt 自动注入 `cache_control: {"type": "ephemeral"}`
- UI 展示缓存命中率和节省的 token 数
- 预期可降低重复请求 60–90% 的成本

### 1.5 本地网关 UI 展示

```
网关状态面板
├── 运行端口：localhost:11434
├── 当前策略：省钱优先 / 质量优先（切换开关）
├── 今日调用：X 次 | 节省估算：¥Y
├── 路由明细（最近 N 条）
│     请求模型 → 实际走 → 耗时 → 积分变化
└── Prompt Cache 命中率：XX%
```

### 第一层：免费 Provider

#### 支持清单

| Provider | 可用模型示例 | 限额特点 | 接入方式 |
|---------|------------|---------|---------|
| Groq | Llama3-70B, Mixtral-8x7B | 每分钟 token 限制 | API Key（免费申请）|
| Mistral | Mistral-7B, Mixtral | 有限免费额度 | API Key |
| GitHub Models | GPT-4o, Llama3, Phi | 每日 token 限额 | GitHub PAT |
| Together.ai | 多种开源模型 | 赠送 $5 额度 | API Key |
| Ollama（本地）| 任意本地模型 | 无限制 | 自动检测 |
| Cloudflare AI | Llama, Mistral 等 | 免费额度 | API Key |

#### 引导流程（Onboarding）

```
Provider 卡片展示（未配置状态）
    ↓ 点击「接入」
显示申请入口链接（如 console.groq.com）
+ 填写 API Key 输入框
    ↓ 填入后点击「测试」
自动发送 ping 请求验证可用性
    ↓ 验证通过
✅ 自动回填到 Worker 配置（base_url + token + models）
显示「已启用，省钱优先时优先调用」
```

对于 Ollama：
```
检测本地 localhost:11434 是否在线
    ↓ 检测到运行中
自动列出已安装模型
    ↓ 一键确认
✅ 自动回填配置，无需手动填写
```

#### 回填逻辑

- 接入成功后自动写入本地路由规则
- 按模型能力自动匹配路由场景（大参数→复杂任务，小参数→简单任务）
- 连续 3 次超时后自动降级，UI 标黄提示重新配置
- 免费额度耗尽时自动跳过，不中断用户请求

### 第二层：订阅 Provider

> 这是本次升级真正新增的核心能力。现有 Worker 支持 API Key，
> 但订阅账号没有标准 API Key，需要中间转换层。

#### 支持清单

| 订阅服务 | 对应模型 | 转换方式 | 风险等级 |
|---------|---------|---------|---------|
| Claude Pro / Team | claude-3-5-sonnet, opus | 本地浏览器代理 | 中 |
| ChatGPT Plus | gpt-4o, o1 | 本地浏览器代理 | 中 |
| Gemini Advanced | gemini-1.5-pro | OAuth Token | 低 |
| GitHub Copilot | gpt-4o | VS Code API 拦截 | 低 |
| Cursor Pro | claude, gpt-4o | 本地代理拦截 | 低 |

#### 核心转换机制

订阅 Provider 在本地运行一个轻量代理服务，将订阅账号的 Web 请求转换为标准 OpenAI 兼容接口：

```
用户工具请求 http://localhost:PORT/v1
       ↓
本地网关 → 订阅代理层（本地进程）
       ↓
订阅代理维持浏览器 Session / Cookie
       ↓
转发到订阅服务 Web API（claude.ai / chat.openai.com 等）
       ↓
将响应格式化为 OpenAI Stream 格式返回
```

#### 引导流程（Onboarding）

```
选择订阅服务（如 Claude Pro）
    ↓
方式 A：浏览器插件辅助（推荐）
  → 引导安装配套浏览器插件
  → 插件自动抓取登录 Session
  → 一键同步到本地代理

方式 B：手动填入 Cookie
  → 打开浏览器 DevTools → Application → Cookies
  → 复制指定 Cookie 值粘贴
  → 本地代理自动解析有效期

    ↓ 验证通过
显示账号状态（有效期 / 剩余限额估算）
✅ 自动回填为「订阅层」Provider，标记模型类型

⚠️ 风险提示：此方式可能违反服务条款，仅供个人学习研究使用
```

#### 保护机制

- 每个订阅账号可设置每日最大调用次数（保护账号安全）
- 多账号支持轮换，单账号超限自动切换下一个
- 账号失效（401/403）立即 UI 告警，不静默失败
- 订阅层请求不进入贡献网络（仅本地消费，不对外分享）

### 第三层：用户分享网络

**即现有 Token Bank Worker 网络，核心能力已具备，无需大改。**

#### 现有能力

贡献者在 Token Bank 客户端填写：
- `base_url`：任意 OpenAI 兼容接口地址
- `token`：对应 API Key
- `models`：该接口支持的模型列表

客户端通过 WebSocket 长连接向 VPS 注册，VPS 将请求调度到在线 Worker。

#### 供给来源（已自然覆盖）

| 贡献者类型 | 填写内容 | 示例 |
|---------|---------|------|
| 本地 GPU 用户 | Ollama / vLLM 地址 | `http://localhost:11434` |
| 正规 API Key 持有者 | 官方 API 地址 + Key | `https://api.anthropic.com` |
| OneAPI / NewAPI 部署者 | 自建聚合网关地址 | `http://my-oneapi.com` |
| 其他 OpenAI 兼容服务 | 任意兼容地址 | 任意 |

#### 消费者侧（积分消耗）

消费者持平台 API Key 调用 `/v1/*`，VPS 调度到合适 Worker，
按模型 `consume_rate` 扣除积分，余额不足返回 402。

## 板块三：模型服务贡献

### 3.1 贡献者完整画像

| 贡献者类型 | 贡献内容 | 每千 output token 积分 | 门槛 |
|---------|---------|---------------------|------|
| 本地 LLM（Open 模型） | GPU 算力 | +8 | 有 GPU |
| 本地 LLM（Premium 级） | 高质量模型 | +50 | 强 GPU |
| API Key 贡献者 | API 额度（Open 模型） | +6 | 有 API Key |
| API Key 贡献者 | API 额度（Premium 模型）| +40 | 有 Premium API Key |
| 订阅代理贡献者 | 订阅账号额度（未来） | +60（风险溢价）| 有订阅账号 |

> 订阅代理贡献当前设计为「本地消费，不对外分享」，
> 未来可作为可选的高收益贡献模式开放，需用户明确授权并承担相应风险。

### 3.2 贡献质量体系（现有，保留）

```
quality_multiplier = 0.4×在线因子 + 0.4×延迟因子 + 0.2×稳定性因子
```

高质量贡献者（低延迟、高稳定性、长在线）获得更高积分加成（最高 1.5x），
并在调度时获得更高优先级，形成正向飞轮。

### 3.3 贡献 UI 面板

```
贡献状态面板
├── 当前状态：运行中 ●
├── 贡献来源：2 个接入点（Ollama + OpenAI API）
├── 今日统计
│     ├── 处理请求：X 次
│     ├── 输出 tokens：Y K
│     └── 获得积分：+Z
├── 健康评分：⭐⭐⭐⭐☆（4.2 / 5）
│     ├── 在线率：98%
│     ├── 平均响应：820ms
│     └── 成功率：99.1%
└── 接入点列表
      ├── Ollama localhost:11434  [chat] Qwen3-32B, Qwen3-7B  ● 在线
      └── OpenAI api.openai.com  [chat] gpt-4o  ● 在线
```

### 3.4 积分经济闭环

```
贡献者 → 提供算力/额度 → 获得积分
                                ↓
消费者 ← 调用 LLM ← 平台调度 ← 积分流通
   ↓
 消耗积分 → 充值购买 → 平台收入 → 维持 VPS 运营
```

贡献者积分可用于：
- 消费平台上其他模型的 API 调用
- 未来：兑换真实奖励（视运营策略）

## 实现优先级建议

### P0（核心价值，优先实现）
1. **本地网关 Proxy** — 板块一的基础，所有路由逻辑的入口
2. **免费 Provider 引导 UI** — 低成本获取供给，用户体验提升显著

### P1（差异化功能）
3. **路由策略引擎**（省钱优先 / 质量优先）— 智能调度的核心
4. **Prompt Cache 自动注入** — 直接降低用户成本，技术实现简单

### P2（扩展供给）
5. **订阅 Provider 转换层** — 核心新功能，参考 CCSwitch/Sub2API
6. **贡献 UI 面板升级** — 展示三层接入点状态

### 暂不实现
- 订阅代理对外贡献（风险管理复杂，待产品成熟后开放）
